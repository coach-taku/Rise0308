## 認証仕様

- Supabase の `users` テーブルを使用した独自認証（名前 + 個別パスワード）
- パスワードは `users` テーブルの `password` カラムで管理し、Supabase ダッシュボードから直接変更しても次回ログイン時に即座に反映される
- ログイン後、ユーザーのロール（`player` / `staff`）に応じてリダイレクト
- 未認証ユーザーは `/login` へリダイレクト
- スタッフ（`role: staff`）のみがユーザー管理画面（`/coach/users`）にアクセス可能

## カルテ機能要件（2026-04-03 追加）

### 目的
3ヶ月に1度の身体測定およびウェイトトレーニングMAX測定の記録を蓄積し、折れ線グラフで推移を可視化する。

### 実装仕様

#### ページ構成
- パス: `/player/karte`
- 対象: 選手（`role: player`）

#### 入力機能
- **身体測定**: 測定日、身長(cm)、体重(kg)、体脂肪率(%)、筋肉量(kg)
- **MAX測定**: 測定日、ベンチプレス(kg)、スクワット(kg)、デッドリフト(kg)
- 同一ユーザー・同一測定日のデータは上書き（upsert）される

#### グラフ機能
- 蓄積データを折れ線グラフ（Recharts）で描画
- 2件以上のデータがある場合にグラフを表示
- 身体測定: 体重・体脂肪率・筋肉量の3系列
- MAX測定: ベンチプレス・スクワット・デッドリフトの3系列

#### 履歴管理機能
- 記録を日付降順でリスト表示
- 各記録に対して編集・削除が可能

#### ナビゲーション
- ボトムナビ（モバイル）とヘッダーナビ（PC）にカルテへのリンクを追加

## チームダッシュボード機能要件（2026-05-11 追加）

### 目的
管理者（コーチ）が手動で選択した複数選手の疲労度・睡眠時間の平均値推移を過去3週間分の折れ線グラフで確認し、チーム全体のコンディション管理・練習計画立案の判断材料とする。

### 実装仕様

#### 画面
- パス: `/coach/dashboard`（既存コーチダッシュボードの「チーム推移」タブとして追加）
- 対象: スタッフ（`role: staff`）のみ

#### 選手選択UI
- チェックボックス形式（ラベルをクリックでトグル）で複数選手を選択可能
- 「全員選択」「全員解除」ボタンを設置
- ページ初期表示時は全選手が選択済みの状態
- 選択人数を「N名選択中 / 全N名」と表示

#### データ集計ロジック
- 選択された選手の `daily_records` から過去21日間（直近3週間）のデータを取得
- 日次単位で選択選手の `fatigue_level`（疲労度）と `sleep_hours`（睡眠時間）の平均値を算出
- データが未入力の日はグラフ上で空白（connectNulls=false）として扱う
- 集計はフロントエンド側で実施（Supabase クエリで対象選手・期間を絞り込み後に計算）

#### グラフ表示
- 疲労度グラフと睡眠時間グラフを縦に2つ並べて表示（単位が異なるため分離）
- 折れ線グラフ（Recharts `LineChart`）を使用
- 疲労度グラフ: X軸=日付（M/d）、Y軸=0〜10スコア、折れ線色=赤（#ef4444）
- 睡眠時間グラフ: X軸=日付（M/d）、Y軸=0〜12時間、折れ線色=青（#3b82f6）
- ツールチップで各日の平均値を表示

#### データ取得関数
- `getTeamConditionRecords(userIds, startDate, endDate)` を `src/lib/data.ts` に追加
- Supabase: `daily_records` テーブルを `user_id IN (...)` + 日付範囲で絞り込む
- デモモード: インメモリの `demoRecords` から同条件で絞り込む
- 既存の RLS ポリシーに準拠したクエリを使用

## ユーザー管理機能要件（2026-05-10 追加）

### 目的
共通の「合言葉」から個人ごとの個別パスワード管理へ移行し、セキュリティを強化する。
管理者（スタッフ）が選手・スタッフの登録・修正・パスワード変更を画面上から行えるようにする。

### 実装仕様

#### ログイン画面（`/login`）
- ラベル・プレースホルダーの「合言葉」表記を「パスワード」に変更
- 各ユーザーが個別に設定されたパスワードでログイン

#### ユーザー管理画面（`/coach/users`）
- 対象: スタッフ（`role: staff`）のみアクセス可能
- 機能:
  - 登録済みユーザー（選手・スタッフ）の一覧表示（パスワード確認含む）
  - 新規ユーザーの登録（名前・ロール・ポジション・初期パスワード）
  - 既存ユーザーの情報修正（名前・ロール・ポジション）
  - 任意ユーザーのパスワード強制変更

#### データ反映仕様
- `users` テーブルの `password` カラムを Supabase ダッシュボードから直接書き換えても、次回ログイン時に即座に反映される
- パスワードは平文で `users.password` カラムに保存（ハッシュ化なし）

#### ナビゲーション
- Header（PC）・BottomNav（スマホ）のスタッフ向けナビに「ユーザー管理」リンクを追加

#### DBスキーマ変更
- `users` テーブルに `position TEXT` カラムを追加
- 既存環境への適用: `ALTER TABLE users ADD COLUMN IF NOT EXISTS position TEXT;`

## 管理者カルテ閲覧機能要件（2026-05-17 追加）

### 目的
指導者が管理者画面から、選手が自律入力したINBODY測定・MAX測定データを正確かつ直感的に把握し、チーム全体の身体データの長期推移を戦術的ピリオダイゼーションやショートタイム・高強度セッション設計の判断材料として活用する。

### 実装仕様

#### 画面
- パス: `/coach/dashboard`（既存コーチダッシュボードの「カルテ」タブとして追加）
- 対象: スタッフ（`role: staff`）のみ

#### 選手選択UI
- ボタン形式（クリックで選択/解除）で閲覧対象の選手を1名選択する
- 選択した選手の名前・ポジションをヘッダーカードで表示する
- 未選択時は「上のリストから選手を選んでカルテを表示します」と案内する

#### 測定データ閲覧（一覧表）
- **INBODY測定タブ**: 身長(cm)・体重(kg)・体脂肪率(%)・筋肉量(kg) を日付降順で表示
- **MAX測定タブ**: ベンチプレス(kg)・スクワット(kg)・デッドリフト(kg) を日付降順で表示
- テーブル形式で全期間の記録を一覧表示する

#### グラフ表示（個人推移 + チーム平均の重ね合わせ）
- 2件以上のデータが存在する場合にグラフを表示する
- 個人データ（実線）とチーム平均（破線）を同一グラフ上に重ね合わせて表示する
- **INBODY測定**: 体重・体脂肪率・筋肉量をそれぞれ独立したグラフで表示（計3グラフ）
- **MAX測定**: ベンチプレス・スクワット・デッドリフトをそれぞれ独立したグラフで表示（計3グラフ）
- 折れ線グラフ（Recharts `LineChart`）を使用
- X軸: 測定年月（YY/M 形式）、Y軸: 各測定値（kg または %）
- ツールチップで各測定時点の値を表示

#### チーム平均の算出ロジック
- 全選手の `physical_records` / `max_training_records` を `measured_date` でグループ化し、各日付の平均値をフロントエンドで算出する
- `getAllPhysicalRecords()` / `getAllMaxTrainingRecords()` 関数を `src/lib/data.ts` に追加
- デモモード: インメモリのデモデータ（複数選手分）から算出する
- Supabase モード: 全件取得してフロントエンドで集計する

#### カラースキーム（既存デザインシステムに準拠）
| 指標 | 個人（実線） | チーム平均（破線） |
|---|---|---|
| 体重 | #e1c614（ブランドイエロー） | 同色・破線 |
| 体脂肪率 | #ef4444（赤） | 同色・破線 |
| 筋肉量 | #22c55e（緑） | 同色・破線 |
| ベンチプレス | #3b82f6（青） | 同色・破線 |
| スクワット | #e1c614（ブランドイエロー） | 同色・破線 |
| デッドリフト | #ef4444（赤） | 同色・破線 |

#### 変更しない既存機能
- 選手が `/player/karte` でデータを入力するフローは変更しない
- 疲労度・睡眠データの同期ロジックおよび選手のプライバシー設定は維持する
- UIのノート型基本構造（中央ロゴ等）は変更しない

## タイムライン過去データ閲覧機能要件（2026-05-20 追加）

### 目的
コーチ（スタッフ）が管理画面のタイムラインタブにて、カレンダーUIで任意の過去日付を選択し、当該日の選手振り返り・コンディションデータを確認できるようにする。

### 実装仕様

#### 画面
- パス: `/coach/dashboard`（既存「タイムライン」タブを拡張）
- 対象: スタッフ（`role: staff`）のみ

#### 日付フィルタUI
- タイムラインタブ内の上部に日付入力（`<input type="date">`）を設置する
- 最大値は本日（`max={today}`）とし、未来日は選択不可
- 日付未選択時: 過去90日間の全件を取得・表示
- 日付選択時: 選択日のみに絞り込んで表示
- 「絞り込みを解除」ボタンで日付選択を初期化できる

#### データ取得ロジック
- 既存の `getAllDailyRecords(startDate?, endDate?)` を再利用する
- 日付未選択時: `getAllDailyRecords(90日前, undefined)` で過去90日間を取得
- 日付選択時: `getAllDailyRecords(選択日, 選択日)` でその日のみ取得
- タイムラインタブのアクティブ化時、および日付変更時に再取得する（独立した state `timelineRecords` で管理）
- 既存の `recentRecords`（コンディション・成長タブ用）は変更しない

#### 表示仕様
- 記録0件の場合は「この日の記録はありません」と表示し、全件表示に戻すボタンを表示する
- データ読み込み中は「データ読み込み中...」のローディング表示をする
- コメント投稿機能はタイムラインタブ内でも引き続き動作する（`timelineRecords` の対象レコードも同時更新）

#### 変更しないこと
- 既存のデータベース構造・データは一切変更しない
- `data.ts` への新規関数追加なし（既存 `getAllDailyRecords` を再利用）
- コンディションタブ・成長タブ・チーム推移タブ・カルテタブのロジックは変更しない
