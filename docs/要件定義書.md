- Supabase Auth（メール/パスワード認証）を使用

## PWA要件（2026-04-02 追加）

### 目的
選手がスマートフォンのホーム画面からアプリを直接起動できるようにする。

### 実装仕様

#### マニフェスト（`/public/manifest.json`）

| 項目 | 値 |
|---|---|
| name | RISE NOTE |
| short_name | RISE NOTE |
| display | standalone |
| background_color | #000000 |
| theme_color | #f97316 |
| start_url | / |
| orientation | portrait |

#### アイコン（`/public/icons/`）

| ファイル | サイズ | 用途 |
|---|---|---|
| icon-192x192.png | 192×192px | Android / PWA標準 |
| icon-512x512.png | 512×512px | Android / PWA大サイズ |
| apple-touch-icon.png | 180×180px | iOS ホーム画面アイコン |
| favicon-32x32.png | 32×32px | ブラウザタブアイコン |
| favicon-16x16.png | 16×16px | ブラウザタブアイコン（小） |

- ソース画像: リポジトリルートの `RISE NOTE.png`（512×512px）

#### Service Worker（`/public/sw.js`）

- ネットワーク優先・キャッシュフォールバック方式
- オフライン時は `/offline.html` を表示
- 外部リクエスト（Supabase API 等）はキャッシュ対象外

#### オフライン画面（`/public/offline.html`）

- アプリデザインと統一されたオフライン専用画面
- オンライン復帰時に自動リロード
- 「再読み込み」ボタンを配置

#### メタタグ（`src/app/layout.tsx`）

- `apple-mobile-web-app-capable: yes`（iOS スタンドアロン対応）
- `apple-mobile-web-app-status-bar-style: black-translucent`
- `apple-mobile-web-app-title: RISE NOTE`
- `mobile-web-app-capable: yes`
- `theme-color: #000000`

## カルテ機能要件（2026-04-03 追加）

### 目的
3ヶ月に1度の身体測定およびウェイトトレーニングMAX測定の記録を蓄積し、折れ線グラフで推移を可視化する。

### 実装仕様

#### ページ構成
- パス: `/player/karte`
- 対象: 選手（`role: player`）

#### 入力機能
- **身体測定**: 測定日、身長(cm)、体重(kg)、体脂肪率(%)、筋肉量(kg)
- **MAX測定**: 測定日、ベンチプレス(kg)、スクワット(kg)、デッドリフト(kg)
- 同一ユーザー・同一測定日のデータは上書き（upsert）される
- 新規作成時はupsert（user_id + measured_date の一意制約）、編集時はIDベースのupdate
- 少なくとも1つの測定値が入力されていることをバリデーション

#### 保存・エラー処理（2026-04-30 修正）
- 保存成功時: トースト通知（緑色）で「保存しました」を表示
- 保存失敗時: トースト通知（赤色）でエラーメッセージを表示
- 削除成功/失敗時: 同様にトースト通知で結果を表示
- Supabase エラー発生時: エラーコード・メッセージ・詳細をコンソールに出力
- 保存後、グラフ・履歴リストに即時反映（ページリロード不要）

#### グラフ機能
- 蓄積データを折れ線グラフ（Recharts）で描画
- 2件以上のデータがある場合にグラフを表示
- 身体測定: 体重・体脂肪率・筋肉量の3系列
- MAX測定: ベンチプレス・スクワット・デッドリフトの3系列
- null値はスキップして線を接続（connectNulls）

#### 履歴管理機能
- 記録を日付降順でリスト表示
- 各記録に対して編集・削除が可能
- 編集時は既存レコードのIDを保持して更新（日付変更にも対応）

#### ナビゲーション
- ボトムナビ（モバイル）とヘッダーナビ（PC）にカルテへのリンクを追加

## RLSポリシー（2026-04-30 追加）

全テーブルに対してRLSを有効化し、`anon` ロールに全操作を許可するポリシーを設定。
クライアント側の `user_id` / `role` によるアクセス制御と組み合わせて運用する。

対象テーブル:
- `users`, `tournaments`, `mandala_charts`, `daily_records`, `comments`
- `physical_records`, `max_training_records`
